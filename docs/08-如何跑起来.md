# 如何跑起来

一条不分叉的路。**先在自己电脑上跑通，再谈自动化。**

---

## 第 0 步：一条命令知道自己卡在哪

```bash
git clone -b claude/blissful-mccarthy-xprsgj https://github.com/NanbuKaguya/artemis.git
cd artemis
python3 -m venv .venv && source .venv/bin/activate
pip install -e '.[data]'

python -m artemis.lite doctor
```

体检器按依赖顺序检查，**停在第一个阻塞项**，给出可以直接复制的命令。
一次报十个问题只会让人不知道先修哪个，而且后九个常是第一个的连锁反应。

修完再跑一次，直到看到「全部就绪」或只剩 ▲ 降级项。

**不要跳过这步去读别的文档。** 体检器就是为了替代读文档。

---

## 第 1 步：刷新交易日历（必做）

```bash
python -m artemis.service calendar-refresh
```

没有它，**节假日会被当成交易日**。系统会在 `basis` 字段标明降级，
但你得先知道去看它。

刻意不硬编码节假日：中国节假日含调休、每年由国务院办公厅通知确定，
写死一个我记错的日期，会让你在休市日下单或在开市日踏空。

---

## 第 2 步：填自选股

```bash
python -m artemis.lite watch        # 首次运行会创建模板
# 编辑 watchlist.txt，每行一个 6 位代码
python -m artemis.lite watch        # 再跑一次，看排雷结果
```

输出长这样：

```
    代码    名称   结论                                     踩雷        提示
600519  贵州茅台 ✓ 通过                                       —          —
000001  平安银行 ❌ 排除         当日涨停（买不进）(涨幅 +9.98%)          —
600666 *ST瑞康 ❌ 排除  ST/退市风险；市值下限(18.0亿)；低价股(1.85元)     —
301888   某妖股 ⚠ 注意                                       —      换手过热
```

**规则只有一条：标 ❌ 的今天不碰。**

不需要相信这套规则的理论。执行一周，你会自己发现哪些「❌」是对的。

---

## 第 3 步：每次下单前记一笔

```bash
python -m artemis.lite log
```

会问你四个问题。写不出理由和失效条件的，它会拒绝记录并告诉你原因；
情绪填 `fomo` 或 `revenge` 会直接建议你 24 小时后再决定。

这不是形式主义。行为金融学里最稳的发现之一是：人会在事后重构自己的
决策理由（"我早就知道会跌"）。**事前承诺是唯一的解药。**

---

## 第 4 步：每周复盘

```bash
python -m artemis.lite review
```

```
临时起意占比 32.0%  ← 超过 10%，执行纪律是你的主要漏洞
冲动交易占比  8.0%  ← 超过 5%
```

`source` 字段（system / discretionary）是整个系统里最值钱的东西。
几个月后它会告诉你：**你的"盘感"到底值多少钱。**
多数人的答案是负数，但你得看见数字才会信。

---

## 到这里就够了

上面四步就是完整的 Lite 用法，**不需要 Hermes，不需要 systemd，
不需要 Level-2，不需要财务数据**。

跑满一个月再考虑下面的可选项。

---

## 可选 A：接本地 Hermes

```bash
export ARTEMIS_LLM_BASE_URL=http://localhost:11434/v1
export ARTEMIS_LLM_MODEL=hermes3

# 连通性 + 上下文体检
python -c "from artemis.copilot.local_llm import LocalLLM; import json; \
  print(json.dumps(LocalLLM().health_check(), ensure_ascii=False, indent=2))"

# 带 AI 解读的简报
python -m artemis.brief premarket --llm
```

**Ollama 用户必看**：24GB 显存以下默认上下文只有 4096 token，
且 OpenAI 兼容接口不接受客户端设置上下文长度。工具签名约占 1400 token，
超了会静默截断。启动时要设：

```bash
OLLAMA_CONTEXT_LENGTH=16384 ollama serve
```

`health_check()` 里看 `native_tool_calls` 和 `text_tool_calls`，
**两个都是 false 说明模型没在用工具**。

---

## 可选 B：自动化（systemd）

只在你已经手动跑满一个月、确认输出有用之后再做。

```bash
sudo REPO=https://github.com/NanbuKaguya/artemis.git \
     BRANCH=claude/blissful-mccarthy-xprsgj \
     bash deploy/install.sh
```

详见 `docs/07-Hermes部署方案.md`。

---

## 可选 C：规则审计（做一次即可）

```bash
python -m artemis.lite audit 200 3      # 抽样 200 只 × 3 年，约 15 分钟
```

在**你自己的数据**上量化每条排雷规则的价值：牺牲了多少平均收益、
换回了多少尾部保护。审计会先跑数据体检，明确告诉你哪些结论不可信。

---

## 卡住了怎么办

```bash
python -m artemis.lite doctor           # 90% 的问题它能直接告诉你
python -m artemis.service health        # 环境细节（时区、依赖、目录权限）
python -m pytest tests/ -q              # 全部测试，全绿说明代码本身没问题
```

三条都正常但还是不对，把这三条的完整输出发我。

---

## 一个诚实的预期管理

第 2–4 步（排雷 + 记录 + 复盘）**这周就能开始，而且这三步是整套系统里
性价比最高的部分**。

Level-2、因子挖掘、完整回测那些，是另一个量级的投入，而且收益远不如
前三步确定。别急着上。

# Level-2 接入指南

## 先回答"该不该接"

**同花顺超级Level-2（288 元/年）无法程序化接入。** 它是客户端内的看板产品，
「机构库存」「龙虎看盘」是同花顺基于原始 L2 做的黑箱衍生指标，没有对外 API。
要从它里面取数据只能逆向客户端协议——违反用户协议，且每次客户端升级都会碎。

它的正当用途是**人工交叉验证**：你自己算出的 OFI、大单净额，
可以拿它的看板对一眼，方向长期背离说明你的计算有问题。

**程序化的 L2 走券商通道**（QMT / xtquant），需券商单独开通权限。

### 值不值那笔钱

L2 对个人最确定的价值在**执行侧**，不在选股侧。按滑点改善算：

| 滑点改善 | 年换手 6x 的年化节省 | 100 万本金 |
|---|---|---|
| 8bp → 6bp | 0.24% | 2,400 元/年 |
| 8bp → 4bp | 0.48% | 4,800 元/年 |
| 8bp → 3bp | 0.60% | 6,000 元/年 |

L2 权限约 2000–3000 元/年（部分券商月费 <200 元）。
**本金低于约 50–60 万时，光靠执行改善覆盖不了这笔费用。**

选股因子那部分不要默认它有用——必须走完整的挖掘 + FDR 流程验证
（见 `docs/04-因子挖掘流水线.md`）。

## 接入步骤

### 1. 体检

```python
from artemis.data.qmt_source import probe
probe("600000")
```

回答两个问题：xtquant 能不能连上（QMT 客户端是否在运行并登录）、
哪些周期真能取到数据（L2 权限是否已开通）。**不要相信券商销售的口头承诺，以这个输出为准。**

### 2. 没有 L2 权限时先跑通链路

```python
from artemis.data.qmt_source import QmtSource
src = QmtSource(level="auto")     # 有 L2 用 L2，没有自动退回 L1 tick
src.resolve_level()               # -> 'l1' 或 'l2'
```

L1 tick（3 秒一笔快照）精度差很多，但足够验证整条流水线。
L2 权限开通后只改一个参数，下游代码不用动。

### 3. 逐笔 → 日频特征

```python
from artemis.data.level2 import daily_features
feat = daily_features(orders, trades, snaps)
```

**L2 进入日频策略的唯一正确姿势是落地时就聚合。**
全市场逐笔单日 30–80 GB，攒不下来也没必要攒。原始 tick 只留最近 N 天用于调试。

产出的日频特征：

| 特征 | 含义 | 备注 |
|---|---|---|
| `ofi` | 订单流失衡 | 文献里最稳健的微观结构量 |
| `order_imbalance` | 委托端买卖力量对比 | 与 ofi 互补（挂单 vs 成交） |
| `book_imbalance` | 十档盘口失衡 | |
| `large_net_ratio` | 大单净流入占比 | 阈值可调 |
| `cancel_ratio` | 撤单率 | **分交易所处理，见下** |
| `spread_bps` / `depth_top1_ratio` | 盘口价差与厚度 | 执行成本的直接输入 |

## 三个会静默出错的坑

### 1. 沪深撤单编码不对称 ⚠️

- **深交所**：撤单是逐笔委托里的一条独立记录（`order_type='CANCEL'`）
- **上交所**：撤单编码在逐笔成交里（`trade_type='C'`）

用同一套代码算撤单率，**沪市会恒为 0 且不报任何错**——你会以为沪市股票都不撤单。
`_order_features()` 分交易所处理这件事，`tests/test_level2.py` 有专门的回归测试守着。

### 2. 主动方判定

逐笔成交里，委托编号大的一方是后到的，即主动方。判反了 OFI 会整体变号——
一个正确的因子变成完全错误的因子，而回测照样能跑出结果。

### 3. 盘口单边枯竭

A 股涨跌停时一侧盘口完全为空。挂单决策函数必须处理这个情况——
而且恰恰是最需要它的时候。`choose_placement()` 对涨停买入/跌停卖出
返回明确结论而不是崩掉，与回测引擎的行为保持一致。

## 执行成本优化

```python
from artemis.execution.cost import BookSnapshot, choose_placement
r = choose_placement(book, side="buy")
```

**一个必须建进模型的东西：逆向选择。**
被动挂单看起来能省半个价差，但你会在价格对你不利时优先成交——
买单挂 bid1，价格下跌才轮到你；价格上涨你根本买不到。
不算这一项会系统性高估被动挂单的收益。

实测结论（非硬编码，由盘口失衡和排队深度推出）：

| 盘口形态 | 买入的最优策略 | 期望成本 |
|---|---|---|
| 买盘厚（失衡 +0.45） | **立即成交** | 4.2bp |
| 卖盘厚（失衡 −0.62） | **被动挂第 3 档** | −7.9bp |

同样是买入，盘口形态不同，最优策略完全相反。这就是 L2 在执行侧的实际价值。

### 事后归因

```python
from artemis.execution.cost import Fill, attribution
attribution(fills)    # 把滑点拆成 冲击 / 时机 两块
```

两块的改善方式完全不同：冲击靠拆单和限制参与率，时机靠缩短决策—执行时滞。
不拆开就不知道该改哪个。

## 合规

程序化交易需向券商报告（2025-07-07 起）。高频认定标准为
单账户每秒申报/撤单 ≥ 300 笔，或全日 ≥ 20000 笔。日频调仓远低于门槛，
但**报告义务仍需履行**。真做日内高频会触发额外报告要求和差异化收费。

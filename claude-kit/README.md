# claude-kit

一套装在 `~/.claude/` 的配置，专治 Claude Code 四种最气人的行为。

```bash
git clone <this-repo> && cd artemis/claude-kit
./install.sh          # 反复运行安全：合并而非覆盖，你已有的配置全部保留
# 然后在 Claude Code 里执行一次 /hooks（或重启 claude）让钩子生效
```

需要 `jq`。`./install.sh --dry` 可以先看会改什么。

---

## 四个病，四味药

| 症状 | 真实病因 | 这套东西怎么治 |
|---|---|---|
| **跑着跑着就出问题** | 改完代码没人立刻检查，错误一路攒到最后才爆 | `verify-edit.sh`：每写完一个文件立刻查语法/lint/冲突标记，**把错误原文塞回它的上下文**，它当场就修 |
| **空转卡住** | ① 卡在权限确认 ② 跑了个永不返回的命令 | `settings.json` 放行 47 类只读命令；`guard-bash.sh` 拦截 `npm run dev`、`vitest`、`tail -f` 这类前台会卡死的命令，并告诉它改用后台运行 |
| **重复犯以前的错** | **CLAUDE.md 里的规矩只是建议，模型可以不看** | `rules.txt`：你写进去的每一条，它执行不了。不是「答应不做」，是 deny |
| **产出不是我要的** | 没对齐就开写；写完不验证就说完成 | `verify-done.sh`：它准备收工时自动跑项目的检查，没过就打回去继续修 —— 不用你先发现再骂一遍 |

---

## 装完后，做这两件事

### 1. 把 `~/.claude/rules.txt` 改成你自己的

这是整套东西里**唯一需要你持续投入、也是回报最高**的一块。

格式：

```
正则  =>  拦下来时给它看的解释
```

用法是一条习惯：**它再犯一次同样的错，别再口头纠正它。** 口头纠正只活到本次
会话结束，下次开新会话它忘得干干净净——这就是"重复犯错"的全部原因。花 20 秒
往这个文件加一行，这个错在你所有项目里永久消失。

```
^npm[[:space:]]   =>  这个项目用 pnpm，把命令换掉再执行。
--no-verify       =>  不许跳过 pre-commit 钩子，钩子失败就去修。
```

项目级的放 `<项目>/.claude/rules.txt`，优先于全局。

### 2. 给每个常用项目写一份 40 行以内的 `CLAUDE.md`

只写四件事：**这项目是干嘛的 / 目录怎么分 / 怎么跑测试 / 有哪些坑**。

> 反直觉但重要：**CLAUDE.md 越长越没用。** 到 200 行时模型会开始挑着看，
> 你以为写了的规矩其实等于没写。真正必须强制的东西不要写在这儿，写进
> `rules.txt`——那个是硬的。

## 不用装任何东西，但收益更大的三个习惯

配置能解决的是机械性问题。剩下的靠这三条，尤其第一条：

**① 复杂任务先按两下 `Shift+Tab` 进计划模式。**
"产出不是我想要的"绝大多数不是能力问题，是它理解的任务和你要的任务从第一步就
不是同一件事。计划模式让它先说方案、你先确认，再动手。**这一条的收益超过本仓库
所有代码的总和。**

**② 换任务就 `/clear`。**
上一个任务的上下文会持续污染下一个判断。它不是"变笨了"，是被三十轮前的
无关信息带偏了。

**③ 任务交代到"能被验证"的程度。**
"优化一下这个函数"→ 不可验证，产出必然随机。
"这个函数在输入为空数组时会抛错，修掉，加个测试覆盖这个 case"→ 可验证，
它自己就能判断做完没有。

## 文件清单

```
install.sh          安装器（合并式，可重复运行）
settings.json       权限白名单 + 禁令 + 四个钩子的挂载点
CLAUDE.md           全局工作约定模板 → ~/.claude/CLAUDE.md
rules.txt           你的禁令表 → ~/.claude/rules.txt
hooks/
  verify-edit.sh    PostToolUse(Edit|Write)  改完立刻查，错误喂回去
  guard-bash.sh     PreToolUse(Bash)         拦阻塞命令 + 执行你的禁令表
  verify-done.sh    Stop                     收工前自检，没过打回（最多打回2次，不会死循环）
  session-brief.sh  SessionStart             开局注入项目现状，省掉摸索
```

## 几个刻意的设计取舍

- **`verify-edit.sh` 只做单文件快检查**（全部加起来 < 3 秒）。全项目类型检查
  很慢，放进这里只会把"空转"问题变得更严重——所以它挪到了收工时的
  `verify-done.sh`。
- **`verify-done.sh` 有熔断**：同一会话最多打回 2 次。检查项如果永远修不好，
  它必须能停下来告诉你，而不是无限循环烧你的额度。
- **所有钩子失败时一律放行（fail-open）**。缺 `jq`、缺 `ruff`、超时——都直接
  退出不阻断。一个把你正常工作卡死的安全网，比没有安全网更糟。
- **`rules.txt` 用 `=>` 而不是 Tab 分隔**。Tab 会被编辑器静默转成空格，
  那样整张规则表会变成一个不报错的哑巴。别用看不见的字符做分隔符。

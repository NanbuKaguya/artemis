# /ship：检查 → 审查 → 提交 → 推送 → 草稿 PR

任何一步不过就停下来，告诉用户卡在哪。

1. **分支**：在 main/master 上就先建分支，命名用 `feat/…`、`fix/…`、`chore/…`。
2. **检查**：跑 `.claude/check.sh`；没有这个文件就跑项目的测试命令。没过就停下来修，修好再继续。
3. **看 diff**：`git diff` 里只应该有这次任务的改动，无关的改动拆出去。
   改动超过几百行，或者碰到了不熟的模块，建议用户先跑 `/code-review`，它会用新的上下文审查。
4. **提交**：标题一句话说清"为什么改"，正文写怎么验证的。几个小提交比一个大提交好。
5. **推送并开草稿 PR**：用 `gh pr create --draft`，或者会话里可用的 GitHub 工具。
   仓库有 PR 模板就按模板填。描述里写四件事：改了什么、为什么改、怎么验证的（命令和结果）、还有哪些风险没覆盖。
6. **回顾**：这次有没有用户纠正了两次的事？有就提议在项目 CLAUDE.md 里加一行。

最后报告 PR 链接，以及第 2 步检查的结果。

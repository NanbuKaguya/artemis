# 工作约定（claude-kit）

## 先分级，再动手

- **S**：一两处改动，心里有数。直接改 → 跑检查 → 报告。
- **M**：涉及多个文件，或者要想一想。先在 plan mode 里出方案，我确认后再写。
- **L**：跨模块、一个会话做不完、或者需求还模糊。先 `/spec`，把规格写进 SPEC.md，再开新会话按规格做。

拿不准就按大一级处理。

## 完成的定义是有证据

- 说"做完了"时附上跑了什么命令、结果是什么。没跑就明说没跑。
- 项目的快速检查在 `.claude/check.sh`。没有这个文件时，先问我怎么验证，或者提议跑 `/setup-project`。
- 改界面就截图看一眼；改性能就给出前后数字。
- 不为了让检查通过而删测试、跳过测试、放宽断言。检查本身有问题，告诉我。

## 改动要小

- 只做我要的那件事。看到别的问题，记下来最后告诉我，不要顺手改。
- 改之前先读相关代码、调用方和测试。
- 不在 main/master 上直接提交：新分支 → 小提交 → 草稿 PR（`/ship`）。

## 卡住时

- 同一个问题我纠正了两次还没好：停下来，总结试过什么、卡在哪，建议我 `/clear` 后换个说法重来。
- 不确定就说不确定。不要编造 API、文件名或命令输出。

## 让约定越用越准

- 同一件事我纠正了两次，就提议在项目 CLAUDE.md 里加一行，写成规则，只加一行。

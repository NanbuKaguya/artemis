# kb-audit —— 找"比证据更已验证"的路径

之前的十九个缺陷**没有一个是靠读代码想出来的**。全部来自：把链条端到端跑一遍
（真实形态的输入，不是玩具 fixture），加上三个问句。

1. **哪条路径能让一条断言比证据所支持的更已验证？**
   这是这个库所有缺陷的共同形状：空白串冒充有值、崩溃脚本被读成打脸、
   `"50万元"` 命中 `"150万元"`、正文换行在 digest 里伪造出整节「已验证断言」。
2. **哪里守了、哪里没守？** 不一致本身就是线索。
3. **还有哪些路径会到达同一个状态？** 同一个缺陷会换一扇门再进来。

另记一条：**所有的门守的都是数据库，真正起作用的产物是 `digest/latest.md`。**
守库不守渲染等于没守 —— 下一个会话读到的是渲染结果。

## 发现怎么处理

先跑 `python3 .claude/hooks/gate.py status`。

- **闸关着** → 只写进 `ashare-kb/ROADMAP.md`「待修（闸开之后）」，格式
  `- [ ] <症状> — <复现> — <日期>`。**严重性不是豁免**：没产出过东西的系统里，
  bug 的影响是零，修它是舒适不是紧急。
- **闸开着** → 可以修，但记住三次代码提交而 verified 不增，闸就关回去。

汇报：发现了几条、写进了哪里、`verified` 仍是几。不报"修了几个"。
